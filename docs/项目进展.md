# 项目进展与交接文档

> 这份文档是给"下一次迭代的 AI 助手"看的交接说明。

## 项目一句话

旺达工作台：任务待办 + 日程日历 + 长期目标 + 此刻灵感 + 数据统计，带桌面小宠物（像素柴犬），暗/浅双主题，全中文，单机使用（多账号架构已预留），可打包成 Windows 安装包分发。

## 技术栈与结构（详见 README.md）

- 前端：React 19 + Vite + TS + Tailwind v4 + TanStack Query + zustand + recharts（client/）
- 后端：Express 5 + Node 内置 node:sqlite（server/），端口 3001
- 桌面：Electron（desktop/），`npm run desktop` 启动像素狗宠物，`npm run dist` 打安装包
- 测试：server 34 个 API 用例（vitest + supertest）+ scripts/ 下的浏览器验收脚本模式

## 用户偏好（重要！）

- **审美**：喜欢精致、克制、专业的风格；最终确认的是"Plane 暗色专业风 + 玫瑰粉强调色"。曾试过奶油软糖风被否（太花哨）
- **浅色模式的粉要"粉嫩"**（2026-10-18 定）：不要 `#f43f5e` 那种硬玫红，定稿为**玫红 h351/s89 + 嫩度 75**，且文字、符号、板块底色必须走同一色相的四档明度，否则会被指出"一个界面里有好几种粉色"
- **宠物**：像素柴犬。用户对它做过多轮精确反馈——只动头顶圆弧、脸保持原版矩形、耳朵要对称（像素级校验过）。**改动它之前务必先问**
- **工作方式**：希望先看到方案确认再动手（用 plan mode 出方案）；改动后要看截图/验证结果；一次只推进一件事，确认后进下一步
- **语言**：全中文交流与界面
- **命名**：板块命名用户有自己的语感（"碎碎念"被否，定为"此刻灵感"）

## 踩过的坑（别再踩）

1. Electron 主进程 spawn 子进程：带中文的绝对路径参数会静默失败 → 用 cwd + 纯 ASCII 相对路径
2. 后端启动窗口期内探测端口会让进程挂死 → 只能监听子进程启动日志（事件驱动）
3. pet.html 里不能 `const desktop`（与 contextBridge 注入的全局标识符冲突，整块脚本解析失败）→ 用别名 `bridge`
4. 拖动透明窗口的残影 → IPC 合帧节流 + backgroundThrottling: false + setOpacity(0.99999)
5. Electron 固定版本号才能打包（"39.8.10" 而非 "^39.0.0"）
6. seed 脚本外键顺序：必须先清 subtasks、先 `UPDATE tasks SET goal_id = NULL` 再删 goals，且 goals 的 sqlite_sequence 要重置（否则重插的 id 不是 1，后续 UPDATE goal_id=1 外键失败）
7. Playwright 合成事件没有真实 screen 坐标 → 测拖动用 CDP `Input.dispatchMouseEvent`（带 screenX/Y，等价真人）；setInputEvent 不可靠
8. 后台 dev 服务会被系统内存压力自动杀掉（非故障）——验证前先确认 3001/5173 活着
9. 图像审查 MCP 工具（analyze_image）部分会话不可用 → 备选：手写 PNG 像素解码采样 / DOM 断言（git log 里有完整范例）
10. **Modal 弹窗必须 createPortal 挂 body**：page-fade 路由动画的 transform 会劫持 fixed 定位的包含块（CSS 规范行为），导致弹窗相对页面内容而非视口定位、越界/错位。Lightbox 同理。另外 Tailwind v4 的 `max-h-full` 在 flex 结构里解析异常，用显式 `max-h-[calc(100vh-2rem)]`；弹窗卡片超高时用遮罩 overflow-y-auto + 卡片 m-auto 实现贴顶滚动
11. 用户屏幕 1280×800（无缩放）——表单类 UI 要控制在 ~700px 高内一屏装下（任务表单已做 3×2 属性网格紧凑化）
12. 贴图的 zod 校验用 `.startsWith('data:image/')` 而非 regex（zod 4 的 startsWith 更直观且错误消息友好）
13. **CSS 自定义属性作用域**：`--rose-fill: hsl(var(--rose-h) ...)` 声明在 `:root` 时，`var(--rose-h)` 在 `:root` 就已替换完毕，之后写在 `body` 上的覆盖对它**完全不生效**——这是用户多次反馈"颜色没变"的真正原因。衍生色必须由 JS 算好后 `body.style.setProperty` 直接写内联值
14. **Edge 打开本地 `file://` 会复用已存在的标签页**：改了 HTML 后 `Start-Process` 打开，用户看到的还是旧页面（尤其窗口开着上百个标签时）。必须换文件名或 `msedge.exe --new-window`，并在页面加 no-cache meta
15. **肉眼看截图比对颜色会被骗**：内容差异会让人误判配色变化。要写审计脚本遍历 DOM 统计每个元素的实际渲染色（如 `scripts/proto/audit-pink.mjs`、`scripts/atm-verify.mjs` 内置），把主观抱怨变成可验证数据；PNG 逐点采样同理
16. **Tailwind v4 换肤的正解是重映射 @theme 色阶**：v4 工具类编译成 `var(--color-rose-500)` 形式，在 `@theme` 里把色阶写成目标字面值、再在 `html.dark` 覆盖暗色值，全站现存类自动跟随——比逐处改类名或 CSS 变量组合都省（且组合 `var(--rose-h)` 在 :root 会被提前求值，是"颜色没变"的老坑）。带透明度的档位（如 tint 底）直接把 alpha 写进色值即可
17. **SSE 消费循环里收到 [DONE] 时，必须先把 rest 缓冲更新再 break**：`if (r.done) break` 前若不 `buf = r.rest`，终末 flush 会把同一批行再消费一遍（delta 重复）。旺达 ai.ts 重构时真实踩到，写用例前自查发现
18. **zustand migrate 返回旧结构数组的 TS 推断坑**：旧 messages 类型是 `{role:'user'|'assistant'}`，直接返回推不出 `ChatMessage[]`（联合的联合不兼容），显式 `as ChatMessage[]` 收窄即可
19. **浏览器验收断言要防"同名元素多处出现"**：会话标题在菜单行和消息气泡各一份（`text=` 计数=2）、历史里的 tool 消息和新 tool 消息混在 messages 里（`.find()` 拿到旧的）——按 `tool_call_id`/`data-testid`/结构特征精确定位，别用裸文本计数
20. **`querySelector('aside')` 会命中左侧导航**（DOM 顺序在前）——测试钩子一律 `data-testid`（柯基侧栏 `corgi-sidebar`）

## 验证方式

- `npm test`（后端 51 用例）、`npm run build`（前端类型+打包）
- 浏览器验收脚本模式：scripts/ 下写过多次（playwright-core + 系统 Chrome），套路是"临时 seed 数据 → 截图/DOM 断言 → reset 清空"
- **柯基三件套验收**：`scripts/verify-corgi.mjs`（基线：流式/快照/周报）、`verify-corgi-width.mjs`（拖宽 6 项）、`verify-corgi-sessions.mjs`（多会话迁移/切换/删除 20 项）、`verify-corgi-tools.mjs`（工具全链路 18 项：mock 上游按调用序路由，建任务真实落库后清理）
- **AI 功能验收**：mock-openai 模式——本地随机端口起假 OpenAI 接口返回固定回复，配置 baseUrl 指向它走全链路（不依赖真实 Key）
- 桌面自检：`$env:ELECTRON_SHOT_DIR="..."; npm run desktop` 自动截图退出
- 小狗交互验证：desktop/ 下曾写过 drag-test / hover-test 模式（CDP 真实输入 + 主进程断言），已删但 git 历史可考
